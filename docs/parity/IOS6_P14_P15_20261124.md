# iumrah Android — iOS 6, P14/P15 checkpoint · 2026-11-24

Reference: `kepler-ios-main 6.zip`. Android baseline: the previous cumulative P00–P13/security patch, not the October public-trip viewer. This is a source checkpoint, not release acceptance.

## P14 changes

| Contract | Implementation |
|---|---|
| Operational itinerary | BookingService + ItineraryResolution: manager schedule first; localized PackageEngine fallback if unavailable; explicit empty schedule is preserved; do not cross authorization boundaries. |
| Booking mutations | BookingStore: require server acknowledgment, serialize mutations, merge latest authorized snapshot, discard stale replies after account change. |
| Guest/account restore | Preserve secure proofs on storage failure; distinguish unavailable secure storage from no trips; reject invalid account/booking responses. |
| Account identity | Strict secure-store reads and writes; do not rotate device identity on transient read failure; guard session mutations against token changes. |
| eSIM | Verify booking ID and server acknowledgment; preserve existing cache for omitted field. |
| Storefront price | Scope quote to current inputs, invalidate on edits, 180s timeout, require positive USD signed server quote and validate any public breakdown. Do not show old published price as current. |
| Storefront sharing | Only share original ID when configuration and verified price match; changed packages require immutable new server snapshot (still missing). |
| FX helper | Use `/api/services/fx` with short timeout and six-hour in-memory cache, not direct CBU; helper is not proof of UI integration. |

## Regression evidence

`bash scripts/verify-ios-booking-v7-store.sh` executes BookingStore against a fake transport and secure-store boundary, and 19 itinerary policy assertions. It tests failed mutations, concurrent changes, stale-account replies, storage failure and mismatched eSIM booking ID. Fake transport tests do not prove compatibility with production responses.

`bash scripts/verify-kotlin-syntax-v8.sh` parses Kotlin sources using compiler PSI; this is not Android compilation or lint.

Run the repository's existing apply-update verifier (`scripts/verify-stage10.sh` and `scripts/verify-build-env.sh`) with the cumulative ZIPs in lexical order. Do not change workflows, signing or bypass security checks.

## Remaining P14 gaps, not accepted

- iOS account-security recovery / phone change (`/security/recovery/{start,confirm}`, `/security/phone/{start,confirm}`), Apple authorization and Apple/Google unlink require full endpoint/UI/state parity review.
- Booking-specific phone verification requires review separately from guest OTP.
- Edited storefront sharing requires `POST /api/storefront/packages/snapshot` and a new server-persisted immutable ID. Android currently blocks mismatched shares, not a replacement for that endpoint.
- Smart isolated session, room gallery, Trip Summary and other earlier visual/function gaps are still open until end-to-end tests; this patch is not a claim of all P00–P13 complete.
- Need actual Business backend staging/live contract tests with authorized test fixtures. No credentials or production mutations used in this checkpoint.
