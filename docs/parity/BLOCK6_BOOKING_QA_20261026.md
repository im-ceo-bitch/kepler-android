# iumrah Android ↔ iOS — Блок 6: Booking

**Дата:** 2026-10-26. **Цель:** source-driven parity к оригинальному iOS `kepler-ios-main 3.zip`, без модификации iOS. Этот отчёт не является актом 100% device parity.

## Исправлено

1. **Номер бронирования / iumrah ID:** во вложенных деталях Android ранее рисовал иконку копирования без клика. Теперь реальная кнопка использует Android `ClipboardManager`, с запретом на копирование пустого/недоступного ID. Лейбл изменён на локализованное «Номер брони» как на iOS.
2. **Восьмизначный iumrah ID:** добавлено свойство `StoredBookingSession.displayPilgrimID` с такой же UI-форматировкой, как `displayPilgrimID` в оригинальном `BookingModels.swift`. Используется в деталях и подзаголовке. Сырой `pilgrimID` для API не изменяется.
3. **Статус оплаты:** `BookingDetailView.shouldShowCheckoutEntry` на iOS учитывает `PAYMENT_PENDING`, `PENDING_PAYMENT`, `WAITING_PAYMENT`, `AWAITING_PAYMENT`, `PAYMENT_AND_DATA_PENDING`, `AWAITING_PAYMENT_AND_DATA` с нормализацией `-` → `_` и проверкой трёх источников статуса. Android теперь использует эквивалент `bookingNeedsCheckout` для CTA, security, счета и политики возвратов. Маршруты `AppChromeStore` оставлены существующими.
4. **Календарь внутри деталей:** превью теперь ограничено четырьмя событиями, и кнопка «Полностью / Full / To‘liq / Тўлиқ» открывает отдельную вкладку расписания. Полная версия продолжает показывать все события и выбор дня.
5. **Смена языка:** детализация повторно локализует ответ itinerary при смене языка, как iOS `.task(id: bookingID|language)`.
6. **Главная вкладка Booking:** ручной pull-to-refresh добавлен в дополнение к прежнему обновлению раз в 60 секунд. Текущие API, checkout, itineraries, Telegram, статусы, удаления и навигация сохранены.

## Валидация

- `bash scripts/verify-stage25.sh` — **PASS**, включая проверки предыдущих блоков 1–5 и `verify-block6-booking-parity.py`.
- `python3 scripts/verify-block6-booking-parity.py --ios /mnt/data/parity_workspace/ios_reference_original` — **PASS** по исходным SwiftUI моделям, календарю и детальным экранам. В репозиторий iOS-путь не внедряется: `--ios` optional для локального QA.
- Изолированный вызов `kotlinc` четырёх затронутых файлов не обнаружил синтаксических ошибок; отсутствующие Android/Compose dependency являются нерешёнными ссылками и не считаются успешной полной сборкой.
- Патч собран как накопительная разница относительно **первоначального Android ZIP + уже установленного v5**, не требует v6–v9 и не содержит исходников iOS.
- Архив ZIP/Deflate проверен, тестово применён к базе и сравнен побайтово по всем файлам восстановленного Android.

## Открыто для дальнейшей приёмки

- **Графическое сравнение:** отсутствуют реальные скриншоты пар iOS/Android для светлой/тёмной темы, длинных локализаций, Dynamic Type / Android Font Scale, небольших экранов, статусов и ошибок. Цвета, размеры, анимации и тени нельзя объявлять абсолютно идентичными.
- **Полная Android-сборка и instrumented тесты:** локальная среда без готового Android SDK/Gradle Wrapper. Требуется Android CI с полноценной компиляцией и запуск на устройстве.
- **Checkout/оплата:** backend side effects, защищённая идентификация, создание/отмена брони и фактическая оплата не проверены end-to-end; никакие серверные контракты не изменены.
- **Свайп удаления других поездок:** iOS использует swipe-to-delete с confirmation dialog. Android уже имел серверный обработчик удаления, но его swipe-жест и диалог в списке ещё не реализованы. Не выдавать этот пункт за совпадающий.
- **Готовность всех вложенных разделов:** паспорта, подтверждение изменений, документальный статус, сервисы сопровождения и управление поездкой потребуют отдельной screenshot/interaction приёмки после сборки.

**Статус:** подтверждённые ошибки исправлены на уровне Android source и тестового применения патча. Блок не принят на 100% без device QA.
