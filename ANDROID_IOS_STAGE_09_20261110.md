# iumrah Android — этап 09, дополнительные возможности iOS (10.11.2026)

## Сверка фактического iOS 7.zip с Android после этапов 01–08

Проверены наличие и маршруты eSIM, Prayer Times, Ziyarats, Gift Cards/Friends, Wallet, Telegram и Trip Planner. Эти функции уже присутствуют в Android; их полное визуальное и интеграционное соответствие iOS здесь не сертифицируется. Главный отсутствовавший экран iOS — ритуальный пошаговый Umrah Flow (`Sources/Umrah Flow/`). В Android уже существовал `UmrahFlowService`, но не было рабочего пользовательского маршрута Umrah Flow.

## Что внесено (Android only)

- Новый `UmrahFlowScreen`: «Начало → Таваф → молитва/Замзам → Са‘й → завершение» с нативной Compose-вёрсткой, монохромной атмосферой, фирменными Cupertino Icons, индикатором прогресса и круговым индикатором семи повторений.
- Таваф: **семь отдельных пользовательских свайпов** подтверждают семь завершённых кругов. Са‘й: семь отдельных проходов с направлениями Сафа→Марва, Марва→Сафа. UI не симулирует физический GPS/датчик и не считает действия автоматически. Пропуск обязательных семи действий заблокирован.
- Сохраняемый на устройстве локальный checkpoint (`SharedPreferences`), предложение продолжить или начать заново. Прогресс не содержит паспортных, платёжных и иных персональных данных.
- Подключён точно тот же рецензированный каталог инструкций `umrah_flow_catalog.json` из предоставленного iOS-репозитория: офлайн-первый запуск, 9 языков в ресурсе, 10 вариантов языка в сетевом API (бенгальский — только онлайн/фолбэк). Не выдуманы дуа и ритуальные инструкции.
- Аудиогид по шагам использует реальные URL проекта, проверяет строгий `HTTPS`-хост и префикс публичного Supabase bucket, не доверяет любым сторонним `https`-ссылкам. Плеер останавливается при смене языка/этапа/уходе с экрана и освобождает ресурсы.
- Сервис каталога теперь берёт доступные переводы и аудио из bundled/сохранённого контента и добавляет новые поля из ответа сервера без удаления полей при частичном ответе.
- Открытие Umrah Flow подключено к существующим интерактивным карточкам главной и к боковой панели. Старый `UmrahAdvisorScreen` сохранён, не удалён. API бронирования/ценообразования, ключевые маршруты приложений и `.github/workflows` не затронуты.
- Обновлён прежний автоматический тест маршрута карточки главной под фактический новый путь iOS.

## Проверки

- `bash scripts/verify-stage12.sh`: пройден, включая существующие статические сверки главной и других модулей после обновления теста маршрута.
- `python3 scripts/verify-stage03-stage04.py`, `verify-stage05-stage06.py`, `verify-stage07-stage08.py`: пройдены.
- `python3 scripts/verify-stage09.py`: пройдена сверка файлов/контрактов/пакетного офлайн-каталога.
- Чистые модели `UmrahFlowProgress.kt` и `UmrahFlowAudioUrlPolicy.kt` собраны через `kotlinc`; отдельно выполнены живые проверки переходов 7+7, запрета пропуска и доменной политики URL. JUnit-тесты добавлены для запуска в Android CI.
- **Не заявляется** успешная полная APK-компиляция, запуск аудио на устройстве, совпадение каждого пикселя SwiftUI/Compose или полный E2E: в текущем контейнере нет Android SDK/Gradle. Эти проверки нужно завершить в Android CI и на устройстве в этапе 10. Первый запуск Flow/сетевые запросы также требуют интеграционного тестирования.

## Применение

1. Загрузить только накопительный архив `iumrah-android-update-20261110-cumulative-stage01-stage09.zip` в корень Android GitHub-репозитория; сделать commit/push.
2. Дождаться применения штатным распаковщиком, не накладывать архивы 01–08 поверх 01–09.
3. Запустить `iumrah Android CI` с `run_release_build=false`; убедиться, что **сама задача compile/assembleDebug** проходит, а не только распаковка ZIP.
4. В установленном Android приложении проверить: главная → Umrah Flow; начало → 7 свайпов Тавафа → молитва/Замзам → 7 переходов са‘й → завершение; возобновление после закрытия, офлайн после первого запуска, русская/узбекская/английская озвучка (если серверная дорожка существует), переключение языка и отсутствие фонового проигрывания.
